# Factorio Settings Serialization Specifications & API Documentation

> [!NOTE]
> This specifications guide is based directly on and supplements the original research found in the [Original Binary Format Documentation](https://github.com/MasterKraid/Factorio-DAT-file-analysis/blob/main/DOCUMENTATION.md).

This document contains the low-level technical specifications, serialization protocols, and API boundaries implemented inside the library. 

---

## 1. Low-Level Binary Specifications

A Factorio `mod-settings.dat` file is a serialized container of a recursive C++ data structure named `PropertyTree`.

### 1.1 File Header Layout

The binary stream begins with a 9-byte header structured as follows:

| Offset (Bytes) | Size (Bytes) | Data Type | Description |
| :--- | :--- | :--- | :--- |
| `0x00` | 2 | `u16` (LE) | Major Version Number |
| `0x02` | 2 | `u16` (LE) | Minor Version Number |
| `0x04` | 2 | `u16` (LE) | Patch Version Number |
| `0x06` | 2 | `u16` (LE) | Build/Developer Version Number |
| `0x08` | 1 | `u8` | System-level boolean header flag |

### 1.2 PropertyTree Type Serialization Protocol

Following the file header, the stream contains a recursive sequence of `PropertyTree` nodes. Every node begins with a 2-byte type definition block:
*   **Byte 0 (Type ID):** A single unsigned byte representing the node's payload structure.
*   **Byte 1 (Any Flag):** A metadata flag used by Factorio to signify generic typed structures (ignored on serialization and written as `0x00`).

The payload following the type block depends on the Type ID:

| Type ID | Type Name | Payload Structure |
| :--- | :--- | :--- |
| **`0`** | `None` | No payload bytes. |
| **`1`** | `Bool` | A single byte (`0x00` for False, `0x01` for True). |
| **`2`** | `Number` | 8-byte double-precision IEEE-754 floating point number (`f64`, LE). |
| **`3`** | `String` | String layout (prefixed nullability byte, optional length descriptors, followed by UTF-8 bytes). |
| **`4`** | `List` | 4-byte count integer (`u32`, LE) representing element count. Each element is serialized as an empty key string placeholder (`0x00 0x00`) followed recursively by a `PropertyTree` node. |
| **`5`** | `Dictionary` | 4-byte count integer (`u32`, LE) representing pair count. Each pair contains a key (serialized as a string) followed recursively by a `PropertyTree` node. |
| **`6`** | `SignedInt` | 8-byte signed integer (`i64`, LE). |
| **`7`** | `UnsignedInt` | 8-byte unsigned integer (`u64`, LE). |

### 1.3 String Layout Protocol

Strings inside the `PropertyTree` structure are serialized with an optional nullability/presence byte:
1.  **Prefix Byte (Offset `0`):** `0x00` signifies a valid, initialized string. `0x01` signifies a null string (uninitialized optional).
2.  **Length Block (Offset `1`):** 
    *   If the length of the string is less than 255 bytes, it is written as a single byte (`u8`).
    *   If the length of the string is equal to or greater than 255 bytes, a marker byte `0xFF` is written, followed immediately by a 4-byte little-endian length integer (`u32`).
3.  **Payload bytes:** UTF-8 encoded string content. Empty settings strings are written as `[0x00, 0x00]` (signifying initialized non-null string of length 0).

## 2. ABI & C-FFI Symbol Specifications

The dynamic library target exports standard C ABI symbols to guarantee zero-overhead integration with host environments such as the Bun JavaScript runtime.

### 2.1 `decode_settings_dat`

Deserializes a binary `mod-settings.dat` memory buffer into a pretty-printed JSON string payload.

```c
char* decode_settings_dat(const uint8_t* dat_ptr, size_t dat_len);
```

*   **Parameters:**
    *   `dat_ptr`: Pointer to the source binary data.
    *   `dat_len`: Length of the source binary buffer.
*   **Returns:** A raw null-terminated char pointer (`char*`) containing the JSON payload or an error string prefixed with `ERROR:`.
*   **Memory Management:** The returning pointer is allocated on the Rust system heap. The host process **must** pass this pointer to `free_string` once read to prevent memory leaks.

### 2.2 `encode_settings_dat`

Serializes a pretty-printed JSON string configuration back into an order-preserving, bit-perfect binary data buffer.

```uint8_t* encode_settings_dat(const char* json_ptr, size_t* out_len);```

*   **Parameters:**
    *   `json_ptr`: Pointer to a null-terminated JSON configuration string.
    *   `out_len`: Output pointer where the compiled binary's length will be written.
*   **Returns:** A raw binary byte array pointer (`uint8_t*`) containing the compiled Factorio format settings, or a null pointer on serialization failure.
*   **Memory Management:** The returning pointer is allocated on the Rust system heap. The host process **must** pass this pointer along with its written length to `free_bytes` to deallocate the memory safely.

### 2.3 `free_string`

Frees C-string allocations generated by `decode_settings_dat` on the Rust heap.

```void free_string(char* ptr);```

*   **Parameters:**
    *   `ptr`: Raw pointer to the string allocation.

### 2.4 `free_bytes`

Frees raw compiled binary allocations generated by `encode_settings_dat` on the Rust heap.

```void free_bytes(uint8_t* ptr, size_t len);```

*   **Parameters:**
    *   `ptr`: Raw pointer to the byte array allocation.
    *   `len`: Length of the byte array allocation matching the length written during encoding.

## 3. Native Heap Memory Management

To maintain absolute safety across the host and ABI boundary, all dynamic allocations are managed under standard Rust heap rules:
*   **No Free-Crossing:** Memory allocated by the Rust allocator must be freed using Rust's allocator interface. The host runtime must never attempt to invoke standard native allocators (`free()`) directly on FFI-returned pointers.
*   **Box Reconstruction:** Heap deallocations are performed by taking ownership of the raw pointer back from the host, reconstructing the native `Box` or `CString` structure, and allowing Rust's standard garbage collection to drop and deallocate the allocations safely.
